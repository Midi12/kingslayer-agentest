# ADR M00-g0: What global gate G0 checks

- Status: accepted
- Date: 2026-09-24
- Module: M00

## Context

G0 applies to every module: typecheck, lint, unit tests, line coverage (85% packages,
70% apps), dependency rules, no `TODO`, `FIXME` or skipped tests, no network in Tier A.
Each module adds a gate `Mxx-G0` that runs it on its packages.

## Decision

`pnpm g0 <package-dir...>` runs per package, from the repository root:

- `tsc --noEmit -p <pkg>/tsconfig.json` (the tsconfig includes `src`, `test` and the
  Vitest config);
- ESLint on the package; errors and warnings both fail;
- `vitest run` in the package with coverage forced on; failed, skipped and todo tests
  fail, as does a run with no tests; the line floor is 70 for `apps/*` and 85 for
  everything else, whatever the package configures;
- dependency-cruiser on `<pkg>/src` with the repository rules;
- a marker scan of `<pkg>/src` and `<pkg>/test` (fixtures included) for `TODO`, `FIXME`,
  `.skip`/`.skipIf`, `.only(`, `.todo(`, `xit(`, `xtest(` and `xdescribe(`;
- proof that the tests ran behind the network guard: the preset's setup file appends a
  line to `$ARGUS_NETWORK_GUARD_REPORT`, and an empty report fails the package.

A module's `Mxx-G0` pass expression reads the metrics (`typecheckFailures`,
`lintErrors`, `lintWarnings`, `tests`, `testsFailed`, `testsSkipped`, `vitestFailures`,
`coverageBelowFloor`, `depViolations`, `markers`, `networkGuardMissing`) and
`exitCode == 0`.

## Consequences

The marker patterns are spelled so that the scanner's own source does not match. Test
inputs that need a marker build it at run time. Mutation testing (Stryker) for pure
decision code is a separate gate of the modules that own such code.
