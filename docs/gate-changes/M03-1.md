# Gate change M03-1: G3 scans independently and records binary bodies; G1 checks usage independently

- Gates: M03-G3 (cassettes are strict), M03-G1 (the official SDK cannot tell the difference)
- Files: `gates/M03.yaml` (G3 pass expression), `packages/testkit/test/m03-gate-g3.test.ts`,
  `packages/testkit/test/m03-gate-g1.test.ts`
- Raised by: independent review, round 1 ("Cassette recorder stores non-UTF-8 request and
  response bodies unredacted", "Some gate metrics check the implementation against itself")

## Problem

G3 recorded JSON bodies only and counted `keyPatternMatches` with the implementation's
own `findKeyMaterial`, so a redaction gap in a shape the tests never produce went
unnoticed: a non-UTF-8 body was stored as base64 with the key inside, and G3 still passed.
Its planted-secret check read the file text only, so a key inside a base64 body was not
seen either. G1 compared `usage.input_tokens` with `estimateJevInputTokens()`, the function
the fake itself calls, so `usageMismatches` could never be non-zero.

## Change

- G3 scans every recorded file a second time with an independent pattern list kept in
  the test (`independentMatches`), decodes every stored `{ base64 }` body and scans the
  decoded bytes for planted secrets and for the independent patterns.
- G3 records three non-UTF-8 bodies carrying a planted key: a request body and a response
  body through the fetch wrapper, and a response body through the proxy (`binaryCases`).
  The test is agnostic about the mechanism: the recorder may refuse the body or redact it,
  but nothing of the key may reach the disk.
- The G3 pass expression gains `metrics.independentMatches == 0 && metrics.binaryCases >= 2`.
- G1 computes the expected `input_tokens` itself from the ADR's rule (⌈UTF-8 bytes of the
  sorted-key compact JSON of `{ state, questions }` / 4⌉) on the body the fake received,
  without the implementation's estimator.

Every existing condition, threshold and count stays as it was; the change only adds
conditions and replaces a self-referential comparison.

## Verified

Against the implementation before the fix, the new G3 cases fail: the files hold three
planted secrets, three `keyPatternMatches` and six `independentMatches`. After the fix
(binary bodies refused with `CASSETTE_BINARY_BODY`) G3 passes with `binaryCases` 3 and
no match of either pattern list. G1 passes with the independent usage check.
