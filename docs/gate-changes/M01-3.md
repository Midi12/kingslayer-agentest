# Gate change M01-3: G4 fixture pairs for old literals and false subschemas

- Gate: M01-G4 (v1 stays additive)
- Files: `packages/contracts/test/__golden__/schema-diff/**` (eight new pairs)
- Raised by: independent review, round 3 ("Additive-only diff misses narrowing when a
  literal set becomes a bounded schema, and misses boolean false subschemas")

## Problem

When an old `const` or `enum` was replaced by a non-literal schema, the diff checked the
old literals only against the new JSON kind, pattern and string length. Numeric bounds,
`multipleOf`, `required` and nested subschemas of the new schema were never applied to
them, so `{const: 5}` to `{type: number, maximum: 3}` passed. A boolean `false`
subschema was read as `{}` (accept anything), so `items`, a property, a pattern
property or a whole schema becoming `false` passed too. No fixture pair covered either
shape, so G4 could not show they are detected.

## Change

Eight new pairs, each expecting `narrowed-type`:

- `literal-const-bounded`: `const 5` becomes `{type: number, maximum: 3}`;
- `literal-enum-minimum`: `enum [1, 2, 3]` becomes `{type: integer, minimum: 2}`;
- `literal-enum-multiple`: `enum [3]` becomes `{type: number, multipleOf: 2}`;
- `literal-object-required`: `const {a: 1}` becomes `{type: object, required: [b]}`;
- `false-items`, `false-property`, `false-pattern-property`, `false-root`: the items
  schema, a property schema, a pattern property schema and a whole schema file become
  `false`.

No threshold, count or coverage figure changes; the fixture count rises from 15 to 23
and every pair must still be detected exactly. The gate file and the G4 test are
unchanged.

## Verified

Before the implementation fix all eight pairs report no change and fail G4. After it
all 23 pairs pass and the comparison with the baseline and its history still finds no
breaking change.
