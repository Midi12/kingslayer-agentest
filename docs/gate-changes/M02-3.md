# Gate change M02-3: G4 only checked the mean full period, not the duty cycle or the number of colours

- Gate: M02-G4 (the blink is a real 1 Hz)
- Files: `apps/fixture-hmi/test/gate-g4.test.ts`
- Raised by: independent review, round 1 ("G4 checks only the mean period, not the
  500/500 duty cycle or the two colours")

## Problem

The spec requires "a true 1 Hz square wave (500 ms on, 500 ms off)". The test averaged
transition-to-transition-to-transition periods (on→off→on) only. A wave with, say, a
200/800 duty cycle still averages a ~1000ms full period and would have passed; nothing
checked that the two half-periods are themselves each ~500ms, and nothing checked that
exactly two colours ever appear (a gradient, or a three-state flicker, would also not
have been caught).

## Change

- Added `meanHalfPeriodMs`: the mean gap between one transition and the next (not one
  transition and the one two after it), asserted to fall within 400–600ms.
- Added `distinctColors`: the count of distinct `getComputedStyle(...).backgroundColor`
  values seen across all samples, asserted to equal exactly 2.

Both are additional assertions on data the test already collects; the existing
`meanPeriodMs` check (900–1100ms) and `transitions >= 4` are unchanged, and
`gates/M02.yaml`'s pass expression is untouched — no threshold, count or coverage figure
the spec states is lowered, two are added.

## Verified

Ran the rewritten test against the current implementation (ADR-M02-2's CSS
`steps(2, jump-none)` animation, 500ms half-period, two colours): passes with
`meanHalfPeriodMs` around 500 and `distinctColors === 2`. A duty-cycle regression was not
separately reproduced (there is no quick toggle for it in the current animation
implementation), but the new assertions are direct: a wave whose half-periods are not
~500ms/~500ms, or that shows more or fewer than two colours, fails them regardless of
what the full-period mean reports.
