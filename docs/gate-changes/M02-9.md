# Gate change M02-9: G1 never checked its own call sequence took effect; four of G2's checks were weaker than the fault they claim to prove

- Gate: M02-G1 (determinism), M02-G2 (every fault does what it says)
- Files: `apps/fixture-hmi/test/gate-g1.test.ts`, `apps/fixture-hmi/test/gate-g2.test.ts`
- Raised by: independent review, round 3

## Problem

**G1** (`playSequence`) POSTs three state-changing calls and never looks at their
response status. If the sim API regressed (for example `start` or `ack` starting to
answer `404`), both servers under test would still render identical, untouched state —
G1 would still pass, having played nothing.

**G2** had four checks weaker than what they claim to prove:

- `no-blink`'s control sampled the alarm row's computed colour once at `t` and once at
  `t+700ms` and asserted they differ. With the real 500/500ms blink wave, two samples
  700ms apart land in different half-periods only when the first sample's phase is in
  `[0,300)` or `[500,800)` of the 1000ms cycle. The test passed every time it was run
  here only because the first sample follows page load almost immediately; on a more
  loaded host, where the first sample's phase can land anywhere in the cycle, the same
  two samples can both be "on" (or both "off") on a perfectly correct build — the check
  was accidentally reliable, not actually robust.
- `locale-fr` asserted only the page title. `conveyorsTitle` is not the whole
  dictionary; a regression that swapped every string *except* the title (or that pointed
  at the wrong dictionary for everything else) would still pass.
- `iframe` asserted the table is visible inside the frame, never that it is *absent*
  from the top document — the fault's whole point.
- `shadow-dom` asserted the table is present once inside the open shadow root, never
  that it is *absent* from the light DOM — same gap, the other fault whose whole point
  is where the table is not.

## Change

- `gate-g1.test.ts`: `playSequence` now asserts each call's expected status (`200`,
  `202`, `200`) and throws if one does not match, so a sim-API regression fails the gate
  instead of silently rendering the same state on both servers.
- `gate-g2.test.ts`:
  - `no-blink`'s control now samples the computed colour repeatedly over a ~1.2s window
    (roughly 1.2 cycles) and asserts at least two distinct colours were seen, and the
    same window under the fault shows exactly one — a check no single unlucky pair of
    samples can pass by accident, on any host.
  - `locale-fr` additionally asserts the Start button reads "Démarrer" (a string from a
    different part of the dictionary than the page title).
  - `iframe` additionally asserts `page.locator('[data-testid="conveyors-table"]')`
    (top document only, unlike `frameLocator`) finds zero elements.
  - `shadow-dom` additionally asserts `document.querySelectorAll('[data-testid="conveyors-table"]')`
    (light DOM; does not pierce a shadow root the way Playwright's own locators do)
    finds zero elements.

No threshold, count or coverage figure the spec states is lowered: G1 still requires
`metrics.pages == 8 && metrics.domMismatches == 0 && metrics.screenshotMismatches == 0`;
G2 still requires all 14 fault tests to pass (`metrics.tested == 14`). The checks now
actually exercise what they claim to, instead of passing by the shape of a frozen clock,
a lucky sample phase, or an assertion that never looked at the DOM region the fault
promises to keep clear.

## Verified

Reverting the `messageKey`/`AlarmKind` fix does not affect these tests (unrelated); to
check the strengthened checks actually bite, each was run against a deliberately
reintroduced version of the bug it now catches:

- `gate-g1.test.ts`: pointing `sourceOf`'s header check at the wrong header name (so
  `startConveyor` and `ackAlarm` still succeed as `api`, but a stray change that instead
  made `/sim/conveyors/:id/start` answer `404` for a moment) makes the new status
  assertion fail as expected; reverting restores a pass.
- `gate-g2.test.ts`'s `iframe`/`shadow-dom` additions were checked by temporarily leaving
  the table fragment duplicated into both the frame/shadow root and the top document —
  both new assertions fail as expected; removing the duplication (the real code path)
  restores a pass.
- `no-blink`'s and `locale-fr`'s strengthened checks were checked by reasoning about the
  sampling window and the dictionary swap directly (both pass against the real fixture
  with no fault-side change needed, since the underlying behaviour was already correct —
  only the checks were too weak to prove it robustly).

`pnpm --filter @argus/fixture-hmi test:gate-g1` and `test:gate-g2` both pass against the
real fixture.
