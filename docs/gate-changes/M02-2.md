# Gate change M02-2: G3 never checked the "none" branch of its own pass condition

- Gate: M02-G3 (datasets are sound)
- Files: `apps/fixture-hmi/test/gate-g3.test.ts`, `apps/fixture-hmi/src/core/dataset-schema.ts`,
  `apps/fixture-hmi/scripts/generate-datasets.ts`, `apps/fixture-hmi/datasets/grounding.jsonl`
- Raised by: independent review, round 1 ("M02-G3 never checks the 'none' branch of its
  pass condition")

## Problem

The spec's pass condition is "each task's answer resolves to exactly one element, or to
none when labelled `none`". In the live-resolution loop, a task with `answer === 'none'`
only incremented `noneTasks` and moved on — nothing checked that the described target is
actually absent from the page. `everyTaskAccountedFor` reported `true` for all 16 `none`
tasks regardless. A `none` task could describe an element that in fact exists (a
mislabelled task, or a regression that adds the element back) and G3 would still pass.

## Change

- `GroundingTask` gets an optional `probe` field: a `data-testid` a wrong pick would
  plausibly match, required whenever `answer` is `"none"`. `generate-datasets.ts` now
  fails at generation time if a `none` task has no probe, and every one of the 16
  existing `none` tasks was given one (an alarm-3 ack button that doesn't exist, a
  settings-page-style delete/export button that was never built, a login "remember me"
  checkbox, a modal "forgot password" link, the ten canvas Start-button testids that only
  exist on `/conveyors`, and the login error banner before any attempt).
- G3's live-resolution loop now asserts each `none` task's `probe` resolves to zero
  elements on that task's page (under its faults), through the same shadow-root/iframe-
  aware `countTestId` used for ordinary answers. A probe that resolves to 1+ elements (or
  a `none` task with no probe) is pushed onto `resolutionFailures`, the same array the
  pass expression already reads via `metrics.resolutionFailures == 0`, so no change to
  `gates/M02.yaml` was needed — the existing pass expression now actually checks what it
  always claimed to.
- `datasets/grounding.jsonl` was regenerated (`pnpm --filter @argus/fixture-hmi
  generate-datasets`); counts are unchanged (134 grounding / 62 breaks, still 16 `none`
  tasks, 20 SVG, 32 fr).

No threshold, count or coverage figure the spec states is lowered — `resolutionFailures
== 0` and `everyTaskAccountedFor == true` are unchanged as pass conditions; they now
cover a code path that previously always trivially passed.

## Verified

Ran G3 against a `grounding.jsonl` row with `probe: 'brand'` substituted for one of the
canvas `none` tasks (`brand` exists on every page via the layout header): the loop
reported `g-canvas-none-c01 (none, probe brand): found 1` and the gate failed, as
expected. Reverted, `pnpm --filter @argus/fixture-hmi test:gate-g3` passes with all 16
probes resolving to zero.
