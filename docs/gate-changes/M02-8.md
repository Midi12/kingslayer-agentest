# Gate change M02-8: G3 leaked a browser context and server on a mid-loop failure

- Gate: M02-G3 (datasets are sound)
- Files: `apps/fixture-hmi/test/gate-g3.test.ts`
- Raised by: independent review, round 2 ("gate suites leak browsers and servers when an
  assertion fails")

## Problem

The live-resolution `it(...)` closed its per-seed `context` and `handle` only after the
whole per-seed loop body (toggling faults, navigating, resolving every task) had run to
completion; nothing in the loop was wrapped in `try`/`finally`. A `fetch` or `page.goto`
throwing partway through (as opposed to a resolution mismatch, which is collected into
`resolutionFailures` and only asserted on after the loop, not thrown) would skip the close
calls and leave a Chromium context and a listening socket behind for the rest of the
Vitest worker.

## Change

The per-seed body is now wrapped in `try`/`finally`; `context` is reset to `undefined` at
the top of each seed's iteration and the `finally` only closes it when it was actually
assigned (so a `loginContext` failure itself, before `context` is set, does not try to
close an already-closed context from a previous seed). `handle` is created before the
`try` and closed unconditionally in `finally`, since a failure to create it means nothing
was opened to leak in the first place.

No threshold, count or coverage figure the spec states is touched; `resolutionFailures ==
0` and `everyTaskAccountedFor == true` are unchanged as pass conditions.

## Verified

`pnpm --filter @argus/fixture-hmi test:gate-g3` (via `pnpm gate M02`) passes, all
existing assertions and metrics unchanged in shape.
