# Gate change M02-4: G5 hard-coded host port 34567

- Gate: M02-G5 (the image works as a service)
- Files: `apps/fixture-hmi/scripts/gate-g5.ts`
- Raised by: independent review, round 1 ("G5 hard-codes host port 34567")

## Problem

CLAUDE.md: "Never hard-code ports in tests: bind port 0 and pass URLs" — other agents
run gates in parallel on the same host. `docker run -p 127.0.0.1:34567:4000` collides if
two G5 runs, or any other process, hold port 34567 at once, and would make the gate flake
or fail for a reason unrelated to the module under test.

## Change

- `docker run` now publishes with `-p 127.0.0.1::4000` (no host port given: Docker picks
  a free one).
- A new `resolveHostPort` helper polls `docker port <container> 4000/tcp` for up to 5s
  (the container's port mapping is available within a moment of `docker run` starting,
  well before `/healthz` itself needs to answer) and parses the assigned host port from
  its output.
- The healthz-polling loop and the final metrics unchanged otherwise, now addressed at
  the resolved port instead of the literal `34567`.

No threshold, count or coverage figure the spec states is touched — `healthyWithinMs` is
still measured from the same start point and still bounded at 5000ms by
`gates/M02.yaml`'s pass expression.

## Verified

`pnpm --filter @argus/fixture-hmi test:gate-g5` (via `pnpm gate M02`) passes:
`buildExit: 0, healthzOk: true, healthyWithinMs: 456, nonRoot: true, uid: '10001'`, with
no port given on the command line.
