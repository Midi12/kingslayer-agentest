# Gate change M01-4: G4's git checks leave the default suite

- Gate: M01-G4 (v1 stays additive)
- Files: `packages/contracts/package.json` (`test:gate-g4`),
  `packages/contracts/test/gate-g4.test.ts`, `packages/contracts/test/gate-g4.git.ts`,
  `packages/contracts/test/support/additive.ts`, `packages/contracts/vitest.git.config.ts`,
  `packages/contracts/tsconfig.json`. `gates/M01.yaml` is unchanged.
- Raised by: merge of `mod/M01` into the integration branch, attempt 1 (M00-G1 failed)

## Problem

M00-G1 exports the tree with `git archive` into a fresh container and runs
`pnpm test`, the default Vitest suite of every package. `gate-g4.test.ts` was part of
that suite and asserted `history.length > 0`, where `history` is every committed
version of `schemas/baseline/` read from git. A `git archive` export has no `.git`, so
the history is empty and the default suite failed; the mechanism, not the schemas, was
wrong. Guarding that assertion with "skip when there is no repository" would have made
the history check silently optional, which is a weakened assertion.

## Change

The test is split by what it needs; nothing is skipped or made conditional.

- `test/gate-g4.test.ts` (default suite, no git): no breaking change against the
  committed snapshot, every fixture pair detected exactly, every required kind proven,
  committed schema files fresh. It passes in a clean export.
- `test/gate-g4.git.ts` (gate only, matched by `vitest.git.config.ts`, outside the
  default `test/**/*.test.ts` glob, as M00 keeps its Docker check
  `gate-g1-clean-clone.ts` out of the default suite): asserts that it runs in a git
  work tree, compares with the latest `v*` tag or else the snapshot, and with every
  committed snapshot version. Outside a work tree all three tests fail. The former
  fallback that treated a missing repository as "no tag" is gone.
- `test:gate-g4` runs both halves, `vitest run test/gate-g4.test.ts && vitest run
  --config vitest.git.config.ts`. Metrics are merged into `$GATE_METRICS`; the names the
  pass expression reads are unchanged (`gitRepository`, `schemasCompared`,
  `breakingChanges`, `baselineRevisions`, `historyBreakingChanges` from the git half;
  the fixture and freshness metrics from the default half). The default half adds
  `snapshotSchemasCompared` and `snapshotBreakingChanges`.

No threshold, count or coverage figure changes, and every assertion of the old test is
still made on every G4 run. The default suite gains a git-free snapshot comparison it
did not have before (the old test compared with the snapshot only when no tag existed).

## Verified

`pnpm --filter @argus/contracts test:gate-g4` passes with the same metrics as before.
With `GIT_DIR=/nonexistent` the default suite (`vitest run --coverage`) passes, 485
tests, and the git half fails all three of its tests.
