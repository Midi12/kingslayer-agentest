# Gate change M02-1: G2's frozen-clock tests never actually exercised no-effect, wrong-state or no-blink, and three checks were weaker than the fault they claim to prove

- Gate: M02-G2 (every fault does what it says)
- Files: `apps/fixture-hmi/test/gate-g2.test.ts`
- Raised by: independent review, round 1 ("the no-effect, wrong-state and no-blink
  tests pass with the fault switched off"; three more checks weaker than the fault
  description)

## Problem

G2 runs every test against a server started with `clock: 'frozen'`. `startConveyor`
records `pendingRunAtMs = now + START_DELAY_MS` and the resolved status only becomes
`Running` once the clock reaches that instant; a frozen clock that is never advanced
stays before it forever. The `no-effect` and `wrong-state` tests clicked Start, waited
50 ms of wall-clock time (which the server's frozen simulator time ignores entirely) and
reloaded — so the row read `Stopped` whether or not the fault was active. Reproduced with
the fault switched off: `status-c02` and `status-c12` both still read `Stopped` after the
same steps. Likewise `no-blink`: under a frozen clock a *normal* unacknowledged row is
already a fixed inline `background-color` with no `class` attribute (ADR-M02-2, "frozen
clock mode, ... a fixed inline `background-color` ... no animation"), so the two
assertions the old test made hold with or without the fault. Three of the fourteen
"visible effect" tests therefore proved nothing about the fault; the gate's 14/14 was not
what the spec's pass condition asks for.

Independently, three checks were weaker than the fault they were meant to prove:
`blocking-modal` only asserted the overlay was `visible`, not that it actually blocks a
click reaching what is under it; `slow-load` only measured page latency although the
fault (`ADR-M02-1`) also delays API responses; `injection`'s hidden-text check asserted
the marker text was present but never that the element is actually hidden.

## Change

- `no-effect` and `wrong-state` now advance the frozen clock past `START_DELAY_MS` via
  `POST /sim/clock` before reloading, and each test first runs the identical sequence on
  an unaffected conveyor as a control, asserting it *does* reach `Running` — so the test
  can only pass if the fault-free path and the faulted path actually diverge.
- `no-blink` now drives a `clock: 'real'` server (this suite's shared server stays
  frozen for the other 13 tests) and compares the computed `background-color` of the
  alarm row sampled ~700 ms apart: first as a control with the fault off (must differ,
  proving a normal row really animates under a real clock), then with `no-blink` on
  (must stay identical).
- `blocking-modal` additionally asserts that clicking `start-c01` through the overlay
  times out (Playwright's actionability check refuses a click whose point resolves to a
  different element on top).
- `slow-load` additionally fetches `/sim/state` and asserts it too takes ≥1000ms.
- `injection`'s hidden-text check additionally asserts the element's rendered bounding
  box is ≤1px in both dimensions (the `.hidden-text` clip technique), not just that
  `isVisible()` would (wrongly) call a 1×1px box hidden.

No threshold, count or coverage figure the spec states is lowered: the gate still
requires all 14 fault tests to pass (`metrics.tested == 14`); the tests now actually
exercise each fault's suppression path instead of a state a frozen clock reaches
identically either way.

## Verified

Reverting the corresponding implementation fix (the `session-expiry`-style guard is not
involved here, but temporarily commenting out `no-effect`'s suppression in
`FixtureSimulator.startConveyor`) makes the rewritten `no-effect` test fail as expected;
restoring it, `pnpm --filter @argus/fixture-hmi test:gate-g2` passes all 14 fault tests.
