# Gate change M01-1: G4 also checks every committed version of the baseline

- Gate: M01-G4 (v1 stays additive)
- Files: `gates/M01.yaml`, `packages/contracts/test/gate-g4.test.ts`
- Raised by: independent review, round 1 ("G4 baseline snapshot is not a protected
  path")

## Problem

Until a `v*` tag exists, M01-G4 compares the schemas generated from the registry with
the committed snapshot `packages/contracts/schemas/baseline/`. That directory is not a
protected path, so an implementation commit could run `export-schemas --baseline`
together with a breaking change and G4 would still pass: the reference moves with the
change it is supposed to catch. Protected paths are defined by M00's gate-guard, which
M01 does not own.

Two defects in the tag branch of the same test were found while fixing it: `git
ls-tree <rev>:<path>` run from `packages/contracts` lists only entries under the
working directory, so the tag's schema set was always empty, and the path was derived
by string slicing. Both would have made G4 fail once a tag existed.

## Change

- G4 now also diffs the current schemas against every version of
  `schemas/baseline/` ever committed (`git log -- :(top)<path>`, each read with
  `git ls-tree --full-tree` and `git show`). Rewriting the snapshot cannot hide a
  breaking change, because the snapshot it replaced stays in the history. It needs no
  branch name or merge-base and also works on the integration branch.
- New metrics `baselineRevisions`, `historyBreakingChanges`, `historyBreakingList`;
  the pass expression adds `metrics.baselineRevisions >= 1 &&
  metrics.historyBreakingChanges == 0`.
- Tag lookup uses `ls-tree --full-tree` and a path computed with `path.relative` from
  the real repository root.

No threshold, count or coverage figure is lowered; the existing checks are unchanged
and one condition is added. A shallow clone still sees at least the boundary commit,
which carries the snapshot. A deliberate `v2` break needs a new schema namespace, not
an edit of v1, so comparing with older v1 snapshots never blocks legitimate work.

## Verified

With `role` removed from `TargetHints` and both `schemas/argus/v1/` and
`schemas/baseline/` regenerated (uncommitted), the existing baseline check passed and
the new history check failed on the removed property.
