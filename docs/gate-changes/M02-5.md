# Gate change M02-5: G2's shadow-dom and injection-canvas checks proved too little, and leaked a browser/server on failure

- Gate: M02-G2 (every fault does what it says)
- Files: `apps/fixture-hmi/test/gate-g2.test.ts`
- Raised by: independent review, round 2 ("the shadow-dom fault silently disables
  Start/Stop"; "the canvas synoptic puts every conveyor's id and status in the DOM,
  and G2's injection test reads that JSON instead of the drawn canvas"; "gate suites
  leak browsers and servers when an assertion fails")

## Problem

`shadow-dom`'s G2 test only asserted the table's DOM structure inside the shadow root
(`querySelectorAll(...).length === 1`); it never clicked anything inside it. The
conveyors page's client script listens on `document` and resolves the clicked element
with `event.target.closest('[data-action]')`; a click inside an open shadow root is
retargeted at `document`-level listeners to the shadow host, so `event.target` is
`div[data-testid="table-shadow-host"]` and `.closest('[data-action]')` on it finds
nothing. Start/Stop silently did nothing under `shadow-dom` — reproduced with Playwright:
0 `/sim/log` entries and the conveyor stayed `Stopped`, where the same click without the
fault, or under `iframe`, worked. G2's shadow-dom test could not have caught this: it
never drove a click.

Separately, the injection test's canvas assertion read
`document.getElementById('synoptic-data').textContent` — a `<script
type="application/json">` data island the canvas page's own markup used to carry (see the
implementation-side fix, `src/core/render/synoptic-canvas.ts`). That data island is what
this review round removed; even before removing it, the check proved the marker was
*present in the page's HTML*, never that it was *drawn on the canvas*, so a regression in
the actual `fillText` call would not have failed this test.

Independently, the `no-blink` sub-test creates its own real-clock server and browser
context and closed them only on the success path (no `try`/`finally`), so a failing
assertion inside it leaked a Chromium context and a listening socket for the rest of the
Vitest worker.

## Change

- Fixed the underlying bug first (implementation, not this gate change):
  `src/core/render/conveyors.ts`'s click listener now walks `event.composedPath()`
  instead of trusting `event.target`, so a click anywhere inside the shadow tree (or
  anywhere else) resolves the real `[data-action]` element it hit.
- `shadow-dom`'s test now also clicks the Start button for a conveyor inside the shadow
  root (via Playwright's locator, which pierces the shadow root itself), advances the
  frozen clock past the start delay, reloads, and asserts the conveyor really reached
  `Running` — the same "advance past the delay and check the resolved state" pattern
  gate-change M02-1 already established for `no-effect`/`wrong-state`.
- The injection test now instruments `CanvasRenderingContext2D.prototype.fillText` via
  `page.addInitScript` before navigating to `/synoptic/canvas`, waits for the page's own
  `data-rendered="1"` marker (set once its async draw finishes), and asserts the marker
  string is among the strings actually painted — while also asserting the served page's
  own HTML (`page.content()`) does **not** contain it, which is the whole point of this
  canvas fault site (OCR/pixel reading required, no DOM shortcut).
- `no-blink`'s server, context and page are now wrapped in nested `try`/`finally`, so a
  failing assertion inside still closes both.

No threshold, count or coverage figure the spec states is lowered: the gate still
requires all 14 fault tests to pass (`metrics.tested == 14`); the shadow-dom and
injection tests now prove strictly more than before.

## Verified

Reverted the `composedPath()` fix locally (back to `event.target.closest(...)`): the
rewritten shadow-dom test fails as expected (`status-c04` stays `Stopped`). Restored it,
`pnpm --filter @argus/fixture-hmi test:gate-g2` passes all 14 fault tests, including the
strengthened shadow-dom and injection cases.
